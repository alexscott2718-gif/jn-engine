Cutscene Web Test Harness Plan PLANNED

2026-06-25 · branch native-port · source plan docs/cutscene_web_test_plan.md

Goal

Generate a testable cutscene catalog from shipped .gam data and make those cutscenes playable on demand from the public web deploy via a button/menu. This is for QA: no campaign progression required, no normal auto-play, and no disruption to the faithfulness audit.

3CAMshot directors already registered at runtime
3MCAnamed sequencers need catalog support
Web buttonnew explicit QA playback path

Implementation Phases

Phase 1 - Catalog

Add tools/build_cutscene_catalog.py to parse every .gam and emit a reviewable catalog. First pass can list each 3MCA and standalone 3CAM, with targets and a goddard_related flag.

{
  "level1b": [
    {
      "tag": "neutron1a",
      "type": "3MCA",
      "shots": ["LABEXP1", "LABEXP2", "WATCHGODDARD"],
      "targets": ["JIM1", "goddardpat2", "C3DGODDARD"],
      "goddard_related": true
    }
  ]
}

Phase 2 - Runtime API

Extend behavior_cutscene.c from one placement-order sequence into web-callable playback:

  • cutscene_request_first_web() for the first deploy.
  • cutscene_count_web(), cutscene_request_web(index), cutscene_active_web(), and cutscene_stop_web() for the selectable menu.
  • Keep direct level loads audit-safe: cutscenes play only when explicitly requested.

Phase 3 - Web UI

Add a compact top-bar control in web/shell.html: a cutscene selector plus Play/Stop. It must work without Campaign mode and return focus to the canvas after clicks.

Phase 4 - Fidelity

After button-driven playback works, improve sequencing: derive true 3MCA -> 3CAM membership, play sounds, apply target animations, honor player-control locks, implement FaceObject, and decode CameraType/ViewFromCamera.
