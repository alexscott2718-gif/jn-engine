# Native Level 1 Map Foundation

Written 2026-05-26. This is the new Linux-native Level 1 foundation. It starts
from source-derived map data rather than capture-camera reprojection or the old
native visual shortcuts.

## Runtime

Use:

```sh
make native-level1
```

or run the engine with:

```sh
JN_NATIVE_LEVEL1=1 ./jnengine
```

To orient the native map with a solved capture keyframe:

```sh
JN_NATIVE_LEVEL1=1 JN_NATIVE_LEVEL1_KEYFRAME=8881 ./jnengine
```

Keyframe descriptors are generated by `make native-level1-map` under:

```text
assets/native/keyframe_cameras/
```

They are converted from `assets/capture/level1_hudfix/keyframe_views.json` into
the native ASE map basis. The descriptor keeps both the native `eye` and the
original `capture_eye` for audit.

`JN_NATIVE_LEVEL1=1` supersedes `JN_HYBRID_LEVEL1` and
`JN_CAPTURE_BACKED_LEVEL1` when multiple flags are set. The runtime uses:

- native camera/projection,
- native GAM simulation,
- `assets/ase/omt/level1_placements.txt` for static map placement,
- every loadable `level1.omt` mesh, including unresolved material slots.

The capture path is not used for camera/world authority.

Native map calibration uses the OMT/ASE basis directly:

```text
runtime translation = (omt_center_x, 0, -omt_center_z)
```

The OMT exporter bakes height into each localized ASE mesh. The runtime keeps Y
translation at 0, but flips placement Z so the native map basis matches solved
capture keyframe cameras.

## Build and Validation Commands

```sh
make                           # build jnengine
make native-level1-map         # regenerate manifest + keyframe camera descriptors
make native-level1             # rebuild manifest, run engine twice (spawn + keyframe 8881),
                               # validate manifest, log markers, nonblank screenshots,
                               # and run alignment check on keyframe 8881
make native-level1-keyframes   # sweep alignment check across every keyframe descriptor
```

`make native-level1` is the single-command structural gate. `make
native-level1-keyframes` is the "do all keyframe descriptors still place the
camera somewhere sensible" check — useful after touching the basis transform
or keyframe-camera generator.

The keyframe alignment check (`tools/validate_native_keyframe_alignment.py`)
projects every loadable mesh's native placement through the keyframe's view *
proj, classifying it as `in_frustum / depth_clipped / off_<edge> /
behind_camera`. Each mesh contributes a bounding-radius slack from its ASE
local AABB so meshes partially off-screen (very common with tilted cameras)
still register as visible. The check then compares native `in_frustum` to the
solver's matched inlier count for that keyframe — high ratios mean the native
basis surfaces more mesh footprints than the solver matched vertices, low
ratios suggest a tilt mismatch.

`make native-level1` exercises:

1. Manifest schema (`jn-native-level1-map-coverage/v2`).
2. Mesh-count, loadable-geometry, missing-bitmap, and per-state buckets.
3. Render-state buckets sum to `mesh_records`; `non_loadable` matches
   `zero_geometry`.
4. `textured + untextured` material slots == `material_slots`.
5. `textured_face_total + untextured_face_total` == `faces`
   (catches silent drift between per-slot face counts and the total).
6. `recovery_hints.top_untextured_meshes` and
   `recovery_hints.top_untextured_material_slots` are non-empty when the
   summary says they should be.
7. Every mesh record carries `render_state`, `material_summary`, and per-slot
   `face_count`, `render_state`, and `omt_mid`.
8. Engine starts in native mode without loading any capture fixture
   (`scene_world.bin`, `scene_reproject.bin`, or `[capture_scene] loaded`).
9. Spawn and keyframe-8881 screenshots are non-blank
   (`build/native_level1_validation.png`,
   `build/native_level1_keyframe_8881.png`).

### Per-mesh fields

```text
name                       OMT mesh name
id                         OMT mesh record id
ase_path                   path to the exported ASE
geometry.verts             ASE *MESH_VERTEX count (runtime authority)
geometry.faces             ASE *MESH_FACE count
geometry.manifest_verts    counts from level1_manifest.json (audit)
geometry.manifest_faces

placement                  [world_x, world_y, world_z] from OMT 3DSP center

classification             textured_visual | foliage | unresolved_visual |
                           collision_or_blocking | terrain_or_surface
render_state               textured | debug_flat | non_loadable (runtime decision)
material_summary           {slot_count, textured_slots, flat_diffuse_slots}
materials[]                per-slot detail
```

### Per-material-slot fields

```text
index            *MATERIAL slot index in the ASE
name             "<mesh>_mat<idx>_mid<omt_mid>"
omt_mid          parsed-out OMT material id (or null)
bitmap           path to PNG, or "" if the OMT canvas was not resolved
bitmap_exists    file exists on disk
diffuse          [r, g, b]
face_count       number of *MESH_FACE entries that reference this slot
render_state     textured | flat_diffuse
```

```text

                               debug_flat -- top 25
```

## What This Solves

- Full static map enumeration is explicit and checked.
- Geometry placement comes from `level1.omt`, not capture camera recovery.
- Native runtime movement reveals a persistent map, not projected keyframe
  fragments.
- Texture/material recovery has a concrete denominator: 258 material slots,
  with per-slot face counts so highest-impact gaps surface first.
- Stale `level1_manifest.json` counts no longer silently disagree with the
  runtime; `stale_geometry_records` flags every mesh that has drifted.

## Known Gaps

1. 132 untextured material slots (2580 faces, ~48% of geometry) render as flat
   diffuse in native mode. Top hits include SCHOOL slots (mid 50, 136, 56) --
   but SCHOOL is shared with another Level 1 sub-level (level1b/level1c), so
   its missing slots are *expected* gaps from loading `level1.omt` alone.
   Non-SCHOOL high-impact slots: fence05 (mid 5, 93 faces), fireHydrant02
   (mid 33, 68 faces), Object02 (mid 37, 64 faces), and a mid-0 fallback
   cluster on Blocks_In / CHIMNEY08 / BLOCKING_03.
2. 67 meshes classified `unresolved_visual` (no bitmap on any slot). All 100
   debug_flat meshes are listed in `recovery_hints.top_untextured_meshes`;
   `unresolved_meshes_full` is the complete list.
3. 1 zero-geometry record: `2D_Trees01.ASE` has `*MESH_NUMVERTEX 0` /
   `*MESH_NUMFACES 0`. The OMT 3DSP parse produced no vertices for it.
4. 16 ASE files have face/vert counts that drift from
   `assets/ase/omt/level1_manifest.json` (`stale_geometry_records`). The ASE
   is authoritative because the loader reads it; the OMT-export manifest needs
   a refresh pass.
5. 4 of the 10 solved keyframes are flagged `tilted` in their descriptors
   (6988, 7633, 7636, 7640). Their original capture cameras pitch >17 deg off
   level, and the keyframe descriptor generator uses `gl_lookat(eye, fwd,
   up=(0,1,0))` which discards roll/pitch. The native render at those
   keyframes shows the right *position* but not the original *orientation*.
   Resolving this requires lifting the full 3x3 capture R matrix into native
   GL basis correctly -- a previous attempt to do `(x, -y, -z)` flip on the
   capture basis vectors produced upside-down images, so the exact capture R
   convention still needs to be nailed down. Until then the alignment
   validator treats tilted descriptors' in_frustum/inlier ratio as
   informational only.

## Next Recommended Work Item

Make tilted-keyframe descriptors faithful. Right now keyframe 8881 (level
camera) renders a recognisable Retroville view that matches the original
capture frame; keyframes 7633/7636 (steep downtilt) project to roughly the
right geometry but with the wrong camera orientation, so they don't *look*
like the corresponding capture frames. The investigation path:

1. Render keyframe 8881 native + compare to the original capture frame 8881
   visually (capture frame archive lives under `build/replay_v4_*.png`). The
   geometry should overlap closely already; any local drift surfaces the
   exact eye/fov/basis fudge factor for the level case.
2. Pick one tilted keyframe (7633 has the cleanest solver inliers at 26) and
   determine the capture R convention by trying every combination of:
   row-major vs column-major interpretation of the 9 floats; world-to-camera
   vs camera-to-world; Y-up vs Y-down. For each candidate, project a known
   ground placement and check whether it lands where the corresponding
   capture frame shows that mesh.
3. Once the convention is known, replace `gl_lookat(up=Y)` in
   `tools/build_native_keyframe_cameras.py` with a direct lift of the 3x3
   capture R rotated into native GL basis.
4. Re-sweep `make native-level1-keyframes` and expect tilted-keyframe
   in_frustum / inlier ratios to climb above 1.0.

Material recovery (the 132 untextured slots) is the lower-priority follow-up.
Skip SCHOOL -- it's a multi-level mesh and its gaps aren't recoverable from
`level1.omt` alone. Start with fence05 mid-5 and the mid-0 fallback cluster
(Blocks_In, CHIMNEY08, BLOCKING_03), which probably share a single root cause
in `tools/omt_mesh_export.py::resolve_bitmap`. Every assignment must come from
a measured OMT canvas record -- do not invent texture mappings.
